# STM32G431 三电阻低边电流采样

本文说明当前工程中 [current_shunt.c](current_shunt.c) 和 [current_shunt.h](current_shunt.h) 的实际实现。代码行为是本文的最终依据。

当前模块已经完成：

- 三电阻低边电流采样；
- OPAMP1/2/3 信号放大；
- ADC1/ADC2 同一 TIM1_TRGO 边沿同步注入；
- 上电零电流偏置校准；
- 按 CCR 排序选择两相并重构第三相；
- 正常 V0 窗口和窄窗口动态采样点；
- 原始值、计数器、采样组合和细分故障码诊断；
- 采样链异常时关闭 TIM1 MOE。

当前模块没有实现：

- Id/Iq 电流 PI；
- 软件过流阈值；
- 转矩模式；
- 跨掉电保存的故障历史记录。

## 1. 总体结构

硬件和软件链路如下：

```text
三相低边采样电阻
        |
        v
OPAMP1 / OPAMP2 / OPAMP3
        |
        v
ADC1 注入组 + ADC2 注入组
        ^
        |
TIM1 CH4 PWM2 -> OC4REF -> TIM1_TRGO
        |
        v
ADC2 JEOS -> ADC1_2_IRQHandler
        |
        v
读取 ADC1/ADC2 JDR1 -> 两相换算 -> 第三相重构 -> FOC 高频任务
```

设计原则是：

> 软件提前选择下一次采样通道，TIM1 在确定的硬件时刻触发转换，ADC 中断只消费已经完成的结果。

不能在 ADC 完成中断中再决定“本次采哪个通道”，因为进入中断时采样已经结束。ADC 中断中计算的 PWM 和采样计划服务于后续周期。

## 2. 硬件参数与通道映射

### 2.1 电气参数

| 参数 | 数值 |
|---|---:|
| 采样电阻 | `0.02 ohm` |
| 综合有效增益 | `1.367 V/V` |
| ADC 参考电压 | `3.3 V` |
| ADC 分辨率 | 12 位，右对齐 |
| 理论零电流偏置 | `2.051 V`，约 2545 counts |
| ADC 每码电流 | 约 `0.0294755 A/count` |

片内 OPAMP 配置为 PGA x16，但采样电阻信号先经过外部电阻网络，所以软件使用的是整个模拟链路的综合有效增益 `1.367`，不是直接使用 16。

### 2.2 引脚和 ADC 路径

| 相 | OPAMP 输入 | OPAMP 输出 | ADC 路径 |
|---|---|---|---|
| U | PA1 / OPAMP1_VINP | PA2 / OPAMP1_VOUT | ADC1_IN3 |
| V | PA7 / OPAMP2_VINP | PA6 / OPAMP2_VOUT | ADC2_IN3 |
| W | PB0 / OPAMP3_VINP | PB1 / OPAMP3_VOUT | ADC1_IN12 |
| W | PB0 / OPAMP3_VINP | OPAMP3 内部输出 | ADC2_CH18 / VOPAMP3_ADC2 |

注意：

- PA1、PA7、PB0 是 OPAMP 输入，不是当前软件直接采样的 ADC 输入；
- ADC1_IN3 和 ADC2_IN3 虽然都叫 CH3，但属于不同 ADC，分别连接 PA2 和 PA6；
- ADC2_CH18 是 OPAMP3 的片内连接，不对应外部 ADC GPIO；
- PA2、PA6、PB1 必须设置为 Analog、No pull；
- 选择 ADC2_CH18 前必须使能 OPAMP3 内部输出。

## 3. ADC 码值和电流换算

换算常量定义为：

```c
#define CURRENT_AMPS_PER_COUNT \
    (3.3f / (4095.0f * 0.02f * 1.367f))
```

数值约为：

```text
CURRENT_AMPS_PER_COUNT = 0.0294755 A/count
```

每相使用各自校准偏置：

```text
Iphase = (offset_phase - adc_raw) * 0.0294755
```

当前硬件极性规定正方向使用 `offset - raw`。上板时必须用已知方向的小电流验证符号，不能只根据原理图假设极性。

理论偏置只用于检查：

```text
2.051 / 3.3 * 4095 = 约 2545 counts
```

运行时换算必须使用校准得到的 `offset_u/v/w`。

## 4. CubeMX 配置

### 4.1 ADC1/ADC2 公共配置

ADC1、ADC2应保持一致：

| 配置项 | 设置 |
|---|---|
| ADC common mode | Independent mode |
| ADC12 kernel clock | PLL，42.5 MHz |
| Clock prescaler | Asynchronous divided by 1 |
| Resolution | 12 bit |
| Data alignment | Right |
| Scan conversion | Enabled |
| Continuous conversion | Disabled |
| Discontinuous conversion | Disabled |
| Low power auto wait | Disabled |
| DMA continuous request | Disabled |
| Regular conversion | Disabled |
| Injected conversion | Enabled |
| Injected oversampling | Disabled |
| Auto injected conversion | Disabled / None |
| External trigger | TIM1 Trigger Out event |
| Initial trigger edge | Rising edge |

ADC1和 ADC2工作在 Independent mode，不使用 ADC dual multimode。两只 ADC 仍然能够同步，因为它们共享 ADC12 内核时钟，并接收同一个 TIM1_TRGO 边沿。

### 4.2 CubeMX 候选 Rank

ADC1候选通道：

| Rank | Channel | Sampling time |
|---|---|---|
| 1 | ADC1_IN3 / U | 6.5 cycles |
| 2 | ADC1_IN12 / W | 6.5 cycles |

ADC2候选通道：

| Rank | Channel | Sampling time |
|---|---|---|
| 1 | VOPAMP3_ADC2 / CH18 / W | 6.5 cycles |
| 2 | ADC2_IN3 / V | 6.5 cycles |

这里的 `Number Of Conversions = 2` 只用于让 CubeMX：

1. 初始化全部候选通道；
2. 写入每个候选通道的 SMPR 采样时间；
3. 生成 PA2、PA6、PB1 模拟 GPIO；
4. 保留 OPAMP3 到 ADC2 的内部连接。

它不是最终运行序列。如果保留 CubeMX 生成的两 Rank JSQR，一个 TRGO 会让每只 ADC 顺序转换两个通道，这不等于同步采四路。

运行时 `current_shunt_tim_update_irq()` 直接覆盖 ADC1/ADC2 的 JSQR。`current_shunt_jsqr()` 不设置 JL，所以每只 ADC 的实际序列长度都是 1：

```text
一个 TIM1_TRGO 边沿
    +-- ADC1 转换一个 Rank
    +-- ADC2 转换一个 Rank
```

因此重新生成 CubeMX 代码后，不能删除运行时单 Rank JSQR 管理代码。

### 4.3 注入队列

CubeMX 保持 Injected Queue Disabled。初始化阶段代码会清理初始注入状态，随后设置：

```c
LL_ADC_INJ_SetQueueMode(adc, LL_ADC_INJ_QUEUE_2CONTEXTS_END_EMPTY);
```

End-empty 模式使已经被 ADC 硬件取走的上下文从 JSQR 清空。这里必须区分两个概念：

- `ADCx->JSQR == 0`：硬件已经取走上下文，转换可能正在进行或已经完成；
- `contexts_armed == 0`：软件已经在 ADC IRQ 中读取 JDR1，并完成结果消费。

因此，`JSQR==0 && contexts_armed==1` 不是队列故障。它表示硬件已经开始转换，但 ADC IRQ 比 TIM1 update 稍晚。驱动此时保持 TRGO 关闭、保留原 `active_pair` 并跳过一次上下文提交，等待 ADC IRQ 读取结果。只有 JSQR 在下一个提交时刻仍非空，才说明硬件上下文确实没有按期消费。

不要在运行中混用 HAL 的动态 `HAL_ADCEx_InjectedConfigChannel()` 和本模块的直接 JSQR 管理。

### 4.4 TIM1 配置

| 配置项 | 设置 |
|---|---|
| Counter mode | Center Aligned mode 1 |
| Prescaler | 0 |
| ARR | 5312 |
| Repetition counter | 1 |
| CH1/2/3 | PWM mode 1，互补输出 |
| CH4 | PWM mode 2，No Output |
| CH4 initial pulse | 5311 |
| Trigger Output / TRGO | OC4REF |
| Trigger Output 2 / TRGO2 | Reset |

中心对齐频率为：

```text
fPWM = 170 MHz / (2 * (5312 + 1)) = 约 16 kHz
```

CH4 不连接功率桥，只生成 ADC 触发波形。CH4 仍必须由 `HAL_TIM_PWM_Start(..., TIM_CHANNEL_4)` 启动。

### 4.5 TRGO、TRGO2 和 CC4 的区别

当前 ADC 必须选择 `Timer 1 Trigger Out event`：

```text
CH4 PWM2 -> OC4REF -> TIM1 MMS=OC4REF -> TIM1_TRGO -> ADC injected
```

三个常见选项的区别：

| ADC 触发选项 | 来源 | 当前工程 |
|---|---|---|
| TIM1_TRGO | CR2.MMS 选择的主触发输出 | 使用，来源为 OC4REF |
| TIM1_TRGO2 | CR2.MMS2 选择的第二触发输出 | 未使用，当前为 Reset |
| TIM1_CC4 | CNT==CCR4 的直接比较事件 | 不使用，中心对齐下一周期可能匹配两次 |

使用 OC4REF 的原因是它有明确的上升沿和下降沿。算法可以在上数半周期使用上升沿，也可以把采样点镜像到下数半周期并改用下降沿。

### 4.6 NVIC 和 ADC 中断源

ADC1、ADC2共用 `ADC1_2_IRQn`。NVIC 启用共享中断并不等于已经启用具体 ADC 标志，本模块只使能 ADC2 JEOS：

```c
LL_ADC_EnableIT_JEOS(ADC2);
```

ADC2 JEOS 作为每周期唯一控制节拍。`ADC1_2_IRQHandler()` 清 ADC2 JEOS 后调用 `current_shunt_adc_irq()`；该函数再检查 ADC1 JEOS，确认两只 ADC 都完成同一硬件触发。

不要同时让 ADC1、ADC2各自调用一次 FOC，否则一个 PWM 周期会重复执行控制任务。

## 5. TIM1_TRGO 采样时刻

扇区 1 示例，假设 `CCR_U > CCR_V > CCR_W`，并把一个周期定义为 `CNT=0 -> ARR -> 0`：

```text
CNT:       0 ---------> ARR ---------> 0
direction:      up              down

vector:    V7 -> V2 -> V1 -> V0 -> V1 -> V2 -> V7
state:    111              000              111

CH4 PWM2: LOW --------- rising -- falling -------- LOW
                           ^
                           ADC normal trigger
```

CH1/2/3 使用 PWM mode 1、高有效：

- CNT 接近 0 时三相上管命令为高，对应 V7(111)；
- CNT 接近 ARR 时三相上管命令为低、互补下管导通，对应 V0(000)。

所以正常 `CCR4=ARR-1` 的上升沿位于 V0 公共低边导通窗口，不是 V7。

## 6. 一个 PWM 周期的软件时序

```text
ADC2 JEOS interrupt
    |
    +-- verify ADC1 JEOS
    +-- read ADC1->JDR1 and ADC2->JDR1
    +-- reconstruct currents with active_pair
    +-- run FOC and calculate next CCR1/2/3
    +-- current_shunt_prepare_pwm() plans pending_pair/CCR4/edge

TIM1 update interrupt
    |
    +-- set TRGO to RESET
    +-- verify previous JSQR contexts are empty
    +-- if JSQR is empty but ADC IRQ is pending: defer one submission
    +-- switch OPAMP3 internal output if required
    +-- write one-rank ADC1/ADC2 JSQR
    +-- latch active_pair = pending_pair
    +-- restore TRGO = OC4REF

next CH4 edge
    |
    +-- hardware starts ADC1 and ADC2 injected conversion
```

几个内部变量的职责：

| 变量 | 含义 |
|---|---|
| `pending_pair` | 下一次计划采样的两相 |
| `active_pair` | 当前 JDR1 结果实际对应的两相 |
| `pending_trigger_edge` | 下一次 JSQR 使用上升沿还是下降沿 |
| `contexts_armed` | 本周期 ADC1/ADC2 上下文是否已经提交 |
| `initialized` | OPAMP/ADC 注入链路是否初始化成功 |
| `ready` | 三相偏置是否校准完成且采样链未故障 |

重构必须使用 `active_pair`，不能使用刚计算出的 `pending_pair`，否则会用下一周期路由解释本周期数据。

## 7. 两相采样和第三相重构

最大 CCR 对应的相具有最短低边导通窗口，因此采另外两相。

| 最大 CCR 相 | pending pair | ADC1 | ADC2 | 重构 |
|---|---|---|---|---|
| U | VW | W / ADC1_IN12 | V / ADC2_IN3 | `Iu=-(Iv+Iw)` |
| V | UW | U / ADC1_IN3 | W / ADC2_CH18 | `Iv=-(Iu+Iw)` |
| W | UV | U / ADC1_IN3 | V / ADC2_IN3 | `Iw=-(Iu+Iv)` |

占空比完全相等时默认使用 UV。

采样组合的通道路由：

| Pair | ADC1 raw | ADC2 raw | OPAMP3 internal output |
|---|---|---|---|
| UV | U | V | Disabled |
| UW | U | W | Enabled |
| VW | W | V | Disabled |

## 8. 采样点算法

参数：

```c
#define CURRENT_SAMPLE_TBEFORE 41U
#define CURRENT_SAMPLE_TAFTER  298U
```

在 170 MHz TIM1 计数时钟下：

```text
TBEFORE = 41 / 170 MHz  = 约 0.241 us
TAFTER  = 298 / 170 MHz = 约 1.753 us
```

ADC 使用 42.5 MHz、6.5 cycles 采样时间。单 Rank 12 位转换粗略为：

```text
(6.5 + 12.5) / 42.5 MHz = 约 0.447 us
```

### 8.1 正常 V0 窗口

```c
if ((PWM_CNT - max_duty) > CURRENT_SAMPLE_TAFTER) {
    sampling_point = PWM_CNT - 1U;
}
```

最大 CCR 到 ARR 的距离足够时，CH4 上升沿放在 ARR 前一个计数。触发后的 ADC 采样保持仍落在 V0 平台内。

### 8.2 在最大 CCR 前采样

```c
else if ((max_duty - mid_duty) >
         ((PWM_CNT - max_duty) * 2U)) {
    sampling_point = max_duty - CURRENT_SAMPLE_TBEFORE;
}
```

当最大相和次大相之间有足够窗口时，在最大 CCR 开关沿之前保留 TBEFORE 裕量。

### 8.3 在最大 CCR 后采样

```c
else {
    sampling_point = max_duty + CURRENT_SAMPLE_TAFTER;
}
```

如果逻辑采样点越过 ARR：

```c
pending_trigger_edge = LL_ADC_INJ_TRIG_EXT_FALLING;
sampling_point = 2U * PWM_CNT - sampling_point - 1U;
```

这会把采样点镜像到中心对齐下数半周期，并用 OC4REF 下降沿触发。

TBEFORE/TAFTER 来自当前硬件和 ST R3_2 策略。更换 MOSFET、栅极驱动、死区、OPAMP 参数、ADC 时钟或前端 RC 后必须重新核算并用示波器验证。

## 9. 初始化和零偏校准

应用初始化顺序位于 `foc_app.c`：

```text
current_shunt_init()
    -> start OPAMP1/2/3
    -> wait 1 ms
    -> calibrate ADC1/ADC2 in single-ended mode
    -> enable ADC1/ADC2
    -> arm injected groups
    -> enable ADC2 JEOS interrupt

foc_timer_init()
    -> start TIM1 and CH4

current_shunt_calibrate(500 ms)
```

校准期间强制清除 TIM1 MOE，功率输出不能开启。

电流零偏校准完成后，用户按键启动电机校准时，功率级按以下顺序使能：

```text
FOC_CALIB_CHARGE_BOOTSTRAP (10 ms)
    -> CCR1/2/3 = 0
    -> 三路低侧管保持导通
    -> 给高侧栅极驱动 bootstrap 电容充电

FOC_CALIB_PWM_NEUTRAL (当前诊断配置 2000 ms)
    -> 恢复 CCR1/2/3 = ARR/2
    -> 正常互补 PWM，但电压矢量为 0

FOC_CALIB_ALIGN_D
    -> vd 从 0 缓升到校准电压
```

bootstrap 过程必须由主循环状态机计时，不能在按键 EXTI 中调用 `HAL_Delay()`；低优先级 SysTick 可能无法抢占 EXTI，从而在 MOE 已开启时锁死中断。中性 PWM 的 2 秒是诊断观察窗口，确认硬件稳定后可以缩短，但不能删除 bootstrap 阶段。

校准分两阶段：

1. `CAL_UV`：UV 组合累计 1024 次，得到 U/V 偏置；
2. `CAL_W`：VW 组合累计 1024 次 ADC1 的 W 数据，得到 W 偏置。

偏置合法范围为闭区间 `2048..3072`。三相全部合法后：

```text
ready = 1
state = CURRENT_SHUNT_READY
```

16 kHz 下采集 2048 个周期约需 128 ms，500 ms 超时包含了启动和中断调度裕量。

`current_shunt_calibrate()` 是阻塞函数，但依赖 TIM1 和 ADC 中断推进状态机，所以调用时必须保持全局中断开启。

## 10. 故障与安全行为

以下情况调用 `current_shunt_fail(reason)`：

- ADC/OPAMP 初始化失败由上层判定；
- 偏置校准超时；
- 任一偏置超出 2048..3072；
- ADC2 中断到来但 ADC1 JEOS 未完成；
- ADC 注入队列溢出 JQOVF；
- 上一 JSQR 上下文没有按期消费；
- 采样点或 CCR 超出合法范围；
- 无效采样组合。

失败动作：

```text
ready = 0
state = CURRENT_SHUNT_IDLE
TIM1 BDTR.MOE = 0
TIM1 TRGO = RESET
```

`g_current_shunt_diag.fault_code` 锁存第一次采样故障，后续故障不会覆盖它。应用主循环仍通过 `current_shunt_is_ready()==0` 进入 `FOC_STATE_FAULT`。

STM32G4 ADC 校准后可能出现 ADEN 写入过早而不生效的问题。驱动按同板 MCSDK 的方式重复置 ADEN 并等待 ADRDY；随后启动/停止一次注入转换，将 CubeMX 生成的两 Rank JSQR 上下文清空，再进入运行时单 Rank 队列模式。

## 11. 公共接口

| API | 调用位置 | 作用 |
|---|---|---|
| `current_shunt_init()` | `foc_init()` | 启动 OPAMP、校准并使能 ADC 注入链路 |
| `current_shunt_calibrate(timeout_ms)` | `foc_init()` | 阻塞完成三相零偏校准 |
| `current_shunt_prepare_pwm(...)` | `foc_set_pwm()` | 规划下一采样组合、CCR4 和触发边沿 |
| `current_shunt_tim_update_irq()` | TIM1 update callback | 提交下一 ADC1/ADC2 单 Rank 上下文 |
| `current_shunt_adc_irq()` | ADC1_2 IRQ | 读取 JDR1、校准累计或重构电流 |
| `current_shunt_get_currents(...)` | FOC/VOFA | 获取最近一次 U/V/W 安培值 |
| `current_shunt_is_ready()` | PWM 门禁/状态检查 | 判断采样链是否可用 |

`current_shunt_adc_irq()` 的返回值：

- 返回 1：本周期已经产生有效运行电流，上层可以执行 FOC 高频任务；
- 返回 0：处于校准、未就绪或故障，不执行正常 FOC 高频任务。

## 12. 中断集成

TIM1 更新中断：

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM1) {
        current_shunt_tim_update_irq();
    }
}
```

ADC1/ADC2共享中断：

```c
void ADC1_2_IRQHandler(void)
{
    if (LL_ADC_IsActiveFlag_JEOS(ADC2) != 0U) {
        LL_ADC_ClearFlag_JEOS(ADC2);
        if (current_shunt_adc_irq() != 0U) {
            foc_tim_irq();
        }
    }
}
```

当前 NVIC 中 TIM1 update 优先级高于 ADC1_2，用于及时提交硬件上下文。UART、按键和其他与控制无关的中断不应长时间占用更高优先级，否则硬件采样时刻虽然不变，电流读取和 FOC 计算可能延迟。

| 8..9 | ADC1/ADC2 注入停止超时 |
| 10..11 | ADC1/ADC2 初始 JSQR 未清空 |
| 12 | 500 ms 零偏校准超时 |
| 13 | ADC 中断到来时没有已锁存上下文 |
| 14 | ADC2 JEOS 到来但 ADC1 JEOS 未到 |
| 15 | 注入上下文队列溢出 |
| 16..17 | UV/W 校准阶段的采样组合不匹配 |
| 18 | 下一提交时刻 JSQR 仍非空，硬件未消费上周期上下文 |
| 19 | 非法采样组合 |
| 20 | 任一零偏不在 2048..3072 |
| 21 | CCR 或采样窗口非法 |

启动后若仍直接进入 `FOC_STATE_FAULT`，先看 `fault_code`，再结合三个计数器判断：

- `tim_update_count=0`：TIM1 没有运行或更新中断没有进入；
- `tim_update_count>0`、`adc_irq_count=0`：CH4/TRGO/ADC 外部触发链未工作；
- `adc_irq_count>0`、`sample_count<1024`：ADC 已触发，在中断一致性、队列或采样组合处失败；
- `sample_count=1024` 且 `fault_code=20`：采样运行正常，但模拟零偏超出允许范围。

`adc_deferred_count` 表示 TIM1 update 到达时，硬件已经消费 JSQR，但 ADC IRQ 尚未读取 JDR1。驱动会保持 TRGO 关闭并跳过本次上下文提交，等待 ADC IRQ 使用原 `active_pair` 消费结果；这种短暂延迟不会再被误判为 `fault_code=18`。如果该计数持续按 PWM 频率增长，说明 TIM1 启动相位或 CCR4 位置仍不正确，应检查 `tim_cnt` 和 `tim_cr1`，而不是放宽采样故障保护。

| 通道 | 内容 |
|---|---|
| `fdata[8]` | U 相电流，A |
| `fdata[9]` | V 相电流，A |
| `fdata[10]` | W 相电流，A |
| `fdata[11]` | `current_shunt_is_ready()`，0 或 1 |

## 15. 常见问题

### 15.1 一直停在 CAL_UV 或 CAL_W

检查：

- TIM1 是否已经启动；
- CH4 是否已经启动；
- TIM1 TRGO 是否为 OC4REF；
- ADC1/ADC2外部触发是否都是 TIM1_TRGO；
- ADC2 JEOS 中断位和 ADC1_2 NVIC 是否开启；
- TIM1 update callback 是否调用 `current_shunt_tim_update_irq()`。

### 15.2 ADC 每周期进入两次

检查：

- ADC 触发边沿是否错误地配置为 Rising and Falling；
- 是否误选 TIM1_CC4 直接比较事件；
- ADC1、ADC2是否都各自执行了一次 FOC；
- RCR 和中心对齐更新节拍是否被修改。

### 15.3 电流有尖峰

检查：

- ADC 实际采样点是否靠近 PWM 切换沿；
- TBEFORE/TAFTER 是否匹配当前硬件；
- OPAMP3 内部/外部路径切换后是否有足够建立时间；
- ADC 6.5 cycles 是否适合前端输出阻抗；
- 地回流、采样电阻 Kelvin 连接和 OPAMP 布局；
- 三相偏置是否稳定且温漂是否明显。

### 15.4 重新生成 CubeMX 后失效

重点核对：

- ADC候选通道和 6.5 cycles 是否保留；
- ADC触发源是否仍为 TIM1_TRGO；
- TIM1 TRGO 是否仍为 OC4REF；
- CH4 是否仍为 PWM2 No Output；
- ADC2内部 OPAMP3 虚拟通道是否保留；
- ADC1_2 和 TIM1 update NVIC 是否保留；
- `current_shunt.c` 是否仍被 Keil 工程编译；
- 运行时单 Rank JSQR 代码是否没有被替换成固定两 Rank HAL 调用。

### 15.5 实例：上电立即出现 `fault_code=18`

本工程曾出现以下现场：

```text
offset_u/v/w = 0
state = CURRENT_SHUNT_IDLE
fault_code = 0x12
init_stage = CURRENT_SHUNT_STAGE_CAL_UV
tim_update_count 持续增加
adc_irq_count = 1
ADC1/ADC2 JSQR = 0
```

最初的代码使用下面的联合条件：

```c
if ((contexts_armed != 0U) ||
    (ADC1->JSQR != 0U) ||
    (ADC2->JSQR != 0U)) {
    fail();
}
```

该条件把“ADC IRQ 还没读取结果”误判成“ADC 硬件没有消费 JSQR”。现场中 JSQR 已经为 0，说明硬件触发和转换链路其实工作，ADC IRQ 只是稍晚到达。故障先把采样状态切回 IDLE，随后到达的 ADC IRQ 即使读到了约 2545 的正常原始值，也不会再累计零偏，所以表现为三相 offset 一直为 0。

修复包含两部分：

1. TIM1 从 `ARR-1`、初始上数方向启动，并在启动前清 UPDATE 标志，减小首周期相位不确定性；
2. `contexts_armed==1 && JSQR==0` 时不覆盖 `active_pair`，跳过一次提交并等待 ADC IRQ；只有 JSQR 非空才锁存 `fault_code=18`。

修复后实测三相零偏约为 `2555/2567/2546`，电流采样完成校准，电机能够开始转动。这个实例说明：排查同步采样不能只看一个软件标志，必须同时观察 JSQR、JEOS、JDR 和中断计数。

### 15.6 实例：功率级使能后 Keil/CoreSight 断连

如果零偏已经正常、`current_shunt.fault_code=0`，但使能 MOE 后 Keil 报 `Cannot access target hardware`，问题已经不属于 ADC 初始化。断连后的 Watch 窗口是分批读取的，未读取字段可能显示 0，快速变化字段也可能来自不同 PWM 周期，不能用这张不完整快照直接判断 FOC 状态。

工程提供全局变量 `g_system_fault_diag`：

| 字段 | 作用 |
|---|---|
| `reset_flags` | 本次启动最早保存的 RCC_CSR，用于判断复位来源 |
| `exception` | `0` 正常，`1` NMI，`2` HardFault，`3` MemManage，`4` BusFault，`5` UsageFault，`6` Error_Handler |
| `cfsr/hfsr/dfsr/afsr` | Cortex 异常状态寄存器 |
| `mmfar/bfar` | 非法访问地址 |
| `tim1_bdtr/ccer/cnt/cr1` | 异常瞬间的 TIM1 状态；捕获后立即清 MOE |
| `backup_valid` | `1` 表示成功读取到 TAMP 备份寄存器中的上一次检查点 |
| `previous_event` | 上一次启动之前留下的普通检查点事件 |
| `previous_pwm_stage` | 上一次检查点的 PWM 阶段：`0` 关闭、`1` 三路低侧、`2` 互补 PWM |
| `previous_calib_state` | 上一次检查点的 `FOC_CALIB_*` 状态 |
| `previous_foc_state` | 上一次检查点的 `FOC_STATE_*` 状态 |
| `previous_tick` | 写检查点时的 `HAL_GetTick()`，单位 ms |
| `previous_tim1_*` | 写检查点之前保存的 TIM1 BDTR/CCER/CCR1..3/CNT/CR1 |
| `previous_boot_reset_flags` | 产生上一次检查点的那次启动的 RCC_CSR；用于抵抗调试器再次 PIN reset 的覆盖 |
| `power_reset_archive_valid` | `1` 表示已冻结“功率输出使能后的第一次复位”证据 |
| `power_reset_event` | 冻结的故障前事件，优先使用此字段定位断线阶段 |
| `power_reset_flags` | 冻结的第一次复位 RCC_CSR，优先使用此字段判断 BOR/PIN/看门狗 |
| `power_reset_pwm_stage/calib_state/foc_state` | 冻结的故障前 PWM、校准、FOC 状态 |

功率阶段检查点事件编号：

| `event` | 含义 |
|---:|---|
| 1 | 已进入本次启动 |
| 2 | TIM1/ADC 电流采样定时器已就绪，MOE 关闭 |
| 3 | 即将关闭 MOE |
| 4 | 即将打开 MOE，三路低侧 bootstrap 充电 |
| 5 | 即将打开 MOE，正常 50% 中性或运行 PWM |
| 10 | 编码器校准开始，即将进入低侧充电 |
| 11 | 进入零电压互补 PWM 观察阶段 |
| 12 | 进入 D 轴对齐并开始从 0 缓升电压 |
| 13 | D 轴对齐后清编码器计数 |
| 14 | 开环旋转搜索 Z/index |
| 15 | 校准正常完成 |
| 16 | 校准失败并已关闭 PWM |
| 17 | RUN 被按键正常停止 |

为了避免 MCU 自动重启后用新的 `event=2` 覆盖故障前状态，代码在校准/运行开始时将 TAMP 备份区标记为待归档。第一次复位会把当时的检查点和 RCC_CSR 冻结到 `power_reset_*`；随后点击 Keil 的 `Reset Target` 或重新进入调试不会覆盖这组数据。正常完成、校准安全失败或按键正常停止会清除归档。

断线后的正确读取步骤：

1. 下载最新 HEX，正常运行到电流采样 ready；
2. 按键复现断线，不要相信弹窗出现后 Watch 中零散刷出的 0；
3. 重新进入调试。如果 Keil 停在 `main()` 第一行，先继续运行，让程序完成 `system_fault_diag_boot_init()` 和 `foc_init()`，然后手动暂停；
4. 在 Watch 中只添加全局结构 `g_system_fault_diag` 并展开；
5. 优先记录 `power_reset_archive_valid/event/flags/pwm_stage/calib_state/foc_state`；若 archive 无效，再记录 `backup_valid` 和所有 `previous_*` 字段。

阶段判读示例：

- `event=4, pwm_stage=1, calib_state=1`：三路低侧刚打开或 10 ms bootstrap 期间复位；重点查低侧驱动极性、栅极驱动电源、功率管和供电短路；
- `event=5, pwm_stage=2, calib_state=2`：50% 零电压互补 PWM 的 2 s 观察期复位；重点查互补极性、死区、上下管直通、栅极驱动和开关噪声；
- `event=12, pwm_stage=2, calib_state=3`：零电压 PWM 已经稳定，施加非零 D 轴电压后复位；重点查相序、电机接线、母线限流、实际相电流和 3.3 V 地弹；
- `event=14, pwm_stage=2, calib_state=5`：对齐通过，在旋转搜索 Z/index 时复位；重点查转动过程的电流、反电动势、相序和编码器；
- `power_reset_flags & 0x08000000 != 0`：BOR/POR，根因优先按电源完整性和地回流处理，不是 ADC 中断软件故障；
- `power_reset_archive_valid=0` 且每次断线后 TAMP 数据也消失：3.3 V/VBAT 可能跌得过深，必须用示波器直接捕获 MCU 3.3 V 和 NRST。

STM32G431 RCC_CSR 复位标志：

| 位 | 掩码 | 含义 |
|---:|---:|---|
| 26 | `0x04000000` | NRST/PIN reset |
| 27 | `0x08000000` | BOR/POR brown-out or power reset |
| 28 | `0x10000000` | 软件复位 |
| 29 | `0x20000000` | 独立看门狗复位 |
| 30 | `0x40000000` | 窗口看门狗复位 |
| 31 | `0x80000000` | 低功耗复位 |

判读原则：

- 重连后 `exception!=0`：优先按 CPU 异常寄存器排查软件；
- `exception=0` 且新的 `reset_flags` 含 `0x08000000`：重点检查 MCU 3.3 V、栅极驱动电源、母线跌落、地弹和去耦；
- MCU 仍在运行、没有新复位标志，只是 SWD 失联：降低 SWD Clock，缩短 SWDIO/SWCLK/GND 连接，检查功率地与调试地回流和开关节点干扰；
- 只有电压命令非零时断连：先降低校准电压和限流，不要用取消保护或提高电流阈值掩盖问题。

当前保守调试默认值为对齐/寻零 `0.20 V`。电流保护采用两级策略：超过 `1.5 A` 连续 8 个有效样本（约 0.5 ms）关断；任意一个有效样本超过 `3.0 A` 则立即关断。历史工程中该电机的额定/最大电流参数为 `5.2 A`，因此上述阈值仍显著低于板卡和电机额定值。确认供电和波形稳定后再逐步增加校准电压，且每一步都要同时观察相电流、母线和 3.3 V。

`0.05 V` 曾出现“保护不再动作但电机完全不动”。原因是当前 SVPWM 电压转计数系数为 `ARR/Udc = 5312/14.23 ≈ 373.3 count/V`，在固定 D 轴角度时，`0.05 V` 只产生约 `1.5×0.05×373.3≈28` 个有效矢量计数；而 TIM1 死区寄存器为 63，历史 MCSDK 的死区补偿量也约为 63 count。当前开环代码尚未实现按电流方向的死区补偿，因此 28 count 的小电压命令会被死区非线性基本吞掉，不能形成持续转矩。

默认值提高到 `0.20 V` 后，理论堵转电流按 `V/Rs` 估算约为 `0.20/0.1=2 A`，仍受 1.5 A 延时保护和 3 A 硬保护约束。以下两个全局变量可直接加入 Keil Watch；修改它们只影响本次 RAM 运行，复位后恢复默认值：

```c
g_foc_calib_align_voltage
g_foc_calib_search_voltage
```

`g_foc_safety_diag.fault_code=2` 表示校准阶段软件过流。动态的 `current_u/v/w` 会在 16 kHz ADC 中断中更新，而 Keil Watch 逐字段读取，因此屏幕上三个值可能来自不同 PWM 周期，不能直接用截图计算三相和。保护代码是在同一次 ADC 中断内读取一组完整电流，三相和仍满足重构约束。

发生过流后使用以下锁存字段，不要使用继续变化的普通电流字段：

| 字段 | 含义 |
|---|---|
| `max_observed_current_a` | 本次运行观察到的最大相电流绝对值 |
| `trip_current_u/v/w_a` | 真正触发保护的同一组 U/V/W 电流 |
| `trip_adc1_raw/trip_adc2_raw` | 触发样本对应的两个 ADC JDR1 原始值 |
| `trip_active_pair` | 触发样本组合：0=UV、1=UW、2=VW |
| `trip_calib_state` | 触发时校准阶段：1=bootstrap、2=中性 PWM、3=D 轴对齐、5=搜索 Z |
| `trip_pwm_stage` | 触发时 PWM 阶段：1=三路低侧、2=正常互补 PWM |
| `trip_tim_cnt` | 保护读取样本后执行时的 TIM1 CNT |
| `trip_hard_limit` | `1` 表示超过 3 A 硬阈值立即关断，`0` 表示超过 1.5 A 达到连续计数 |

同板历史 MCSDK 工程在 `CHARGE_BOOT_CAP` 状态中先调用 `R3_2_TurnOnLowSides(..., 0)`，等待约 10 ms 后才调用 `R3_2_SwitchOnPWM()`。当前工程必须保留等效流程。若按键前采样完全正常、按键设置 MOE 后立即失联，而当前代码跳过了 bootstrap 充电，应优先补齐启动时序，不能继续怀疑 ADC 零偏。

## 16. 维护边界

修改以下参数时必须同步更新代码、CubeMX 和本文：

- TIM1 时钟、ARR、PWM 频率或中心对齐模式；
- ADC12 时钟、分辨率、采样时间；

- 电流方向定义；
- TBEFORE/TAFTER；
- ADC中断源和优先级；
- VOFA 通道映射。

本模块的关键不变量是：

1. 每周期 ADC1、ADC2各转换一个注入 Rank；
2. 两只 ADC 使用同一个 TIM1_TRGO 边沿；
3. JSQR 和 OPAMP3 路由只在 TRGO 关闭时提交；
4. JDR1 必须使用与它一起锁存的 `active_pair` 解释；
5. 电流采样未 ready 时禁止开启 PWM 主输出。

- 原厂工程启用了 COMP/DAC/TIM1 BKIN 作为硬件过流保护；当前工程暂未接入 BKIN，这影响硬件级保护能力，但不是“按键后不转”的直接原因。

本次定位到的直接软件问题：

1. svpwm_calc() 的旧扇区表会把命令电压矢量反向。用当前工程的旧算法计算：
   - 输入 (+0.2 V alpha, 0 beta)，由 CCR 反推得到 (-0.2 V alpha, 0 beta)；
   - 输入 (0 alpha, +0.2 V beta)，由 CCR 反推得到 (0 alpha, -0.2 V beta)。
   也就是输出恒为 -Vref，D 轴对齐、开环搜索 Z、编码器电角度 offset 都会被带到相反方向。
2. 当前工程没有电流 PI，也没有基于电流方向的死区补偿。TIM1 死区寄存器为 63，历史 MCSDK 的 DTCOMPCNT 也约为 63 count。旧默认 g_target_voltage=0.10 V 只产生约 65 count 的相间有效差值，0.20 V 约 129 count，接近 2*63=126 count 的死区影响；因此小电压命令很容易“功率变大但没有连续转矩”。
3. 当前启动流程原先强制先做 ABZ Z/index 校准。用户手册说明本板支持 I2C、ABZ、ABC、SPI 多类接口，原厂默认出厂程序是 STO/PLL 无感 FOC，并不要求 ABZ/Z。若当前电机没有接可靠 Z 脉冲，一按键会一直停在搜索 Z 或超时，表现为“没有进入正常运行”。

本次代码修复：

- MDK-ARM/Code/foc/Core/foc_math.c：svpwm_calc() 改为逆 Clarke 后做 common-mode injection 的标准七段 SVPWM。现在输入 (+alpha,+beta) 能由 CCR 反推回 (+alpha,+beta)，不再反向。
- Core/Src/main.c：默认 g_startup_require_encoder_calibration=0，按键直接进入低速开环功率级测试；如需恢复“先 ABZ/Z 校准，再第二次按键运行”，在 Keil Watch 中把该变量改为 1。
- Core/Src/main.c：默认开环测试改为 g_target_voltage=0.30f、g_target_speed_rpm=100.0f，让命令明显越过死区无效区，同时仍受现有软件过流保护约束。
- MDK-ARM/Code/foc/App/foc_calib.h：若启用编码器校准，FOC_CALIB_ALIGN_VOLTAGE 和 FOC_CALIB_SEARCH_VOLTAGE 默认为 0.30f。

没有修改的点：

- 未交换 TIM1 CH1/CH2/CH3。20 mΩ 原理图的 EG2124A 输入/输出标注容易让人怀疑 CH1 和 CH3 交叉，但原厂 122.ioc 明确标注 PA8/TIM1_CH1=M1_PWM_UH、PA9/TIM1_CH2=M1_PWM_VH、PA10/TIM1_CH3=M1_PWM_WH，当前工程也保持这个软件相序。
- 未实现 Id/Iq 电流闭环。原厂可正常启动的 MCSDK 工程是电流闭环启动，启动相电流目标约 1.5 A；当前阶段仍是安全开环测试，目标是验证功率级、SVPWM 方向、电流采样和相序。

上板验证顺序：

1. 下载最新 HEX 后先不上按键，确认 current_shunt_is_ready()=1、g_current_shunt_diag.state=3、fault_code=0、三相 offset 约 2545。
2. 保持 g_startup_require_encoder_calibration=0，按键后应直接进入 FOC_STATE_RUN，g_foc_pwm_stage=2，vf.svpwm_sector 应随开环角度变化。
3. 先用 g_target_voltage=0.30、g_target_speed_rpm=100 观察是否缓慢转动；若只抖动不转，把 g_target_speed_rpm 降到 30~60 rpm，或把 g_target_voltage 分步调到 0.35/0.40 V，同时观察 g_foc_safety_diag.peak_current_a 和 max_observed_current_a。
4. 若转向反，优先把 g_target_speed_rpm 改成负值验证，不要先换 ADC 电流极性。
5. 若仍完全不动但电流明显上升，重点怀疑电机三相线序与软件 U/V/W 不一致；可只交换任意两根电机相线做验证，确认后再决定是否在软件里调整相序。
6. 只有在开环已经能稳定转动后，再把 g_startup_require_encoder_calibration=1 测 ABZ/Z 校准；若没有 Z 线或 Z 脉冲不可靠，不要把该校准作为启动前置条件。

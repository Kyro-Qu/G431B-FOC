# 05 · 双电机扩展指南

> 本板只有一套功率级，所以**默认单电机（`FOC_NUM_AXES=1`）**，
> 双轴框架完整预留。本篇讲：怎么开启双轴、虚拟轴能干什么、
> 接第二套真硬件要做哪几步。

---

## 1. 开启双轴：改一个宏

[foc_config.h](../MDK-ARM/Code/foc/HAL/foc_config.h) 里把
`FOC_NUM_AXES` 改成 2 重新编译即可。此时：

| | 轴 0 | 轴 1（虚拟） |
| -- | -- | -- |
| PWM | TIM1 三相互补 | 空函数 |
| 电流采样 | ADC1/2 + OPAMP×3 | 无（接口传 NULL） |
| 传感器 | TIM4 ABZ 编码器 | 无（接口传 NULL） |
| 能做什么 | 全部四种模式 | 开环 V/f 数学运行 |

虚拟轴的意义：**证明多轴框架真实可用**。开启双轴编译后可以直接试：

```
a 1        ← 切到轴 1
e 1        ← 使能
rpm 300    ← 虚拟轴开环"旋转"
```

VOFA ch15 会看到轴 1 的电角度在锯齿推进——两个轴的控制环真的在并行跑，
互不干扰。轴 0 的所有操作照常。

## 2. 框架为什么天然支持双轴

回顾架构（详见 02 篇）：

1. **算法层零全局状态**：`foc_motor.c` 里没有任何全局变量，
   所有状态都在 `foc_motor_t` 对象里；
2. **硬件访问全部走接口表**：对象绑定哪张表，就驱动哪套硬件；
3. **每轴独立的快环入口**：`foc_motor_fast_loop(&g_foc_motors[n])`
   可以从任何中断调用。

所以"加一个电机"= 加一张接口表 + 一个对象 + 一个中断入口，
**Core/App 层代码一行不用改**。

## 3. 接真硬件的完整步骤

假设第二套功率级用 TIM8（G431 的另一个高级定时器）+ ADC 注入组。

### 第 1 步：CubeMX 配置外设

对照轴 0 的配置照抄一份：
- TIM8：中心对齐 PWM，三路互补输出 + CH4 触发（TRGO=OC4REF），
  死区、OSSR/OSSI 与 TIM1 相同；
- 电流采样：第二组运放/ADC 注入通道（G431 有 OPAMP1~3，双电机时
  采样方案需要复用规划，或用外部运放 + 普通 ADC 通道）；
- 编码器：TIM2 或 TIM3 编码器模式（PA0/PA1 或 PB4/PB5 等）；
- 使能对应 ADC 中断。

> 现实约束：G431CBU6 (48 脚) 引脚有限，本板 PCB 也没有引出第二套半桥。
> 真正的双电机建议用 G431 的兄弟型号 G474（引脚更多）或双板 CAN 组网
> （VESC 的做法）。框架代码对这两种都适用——单板双轴改绑定，
> 双板组网则每板跑一轴。

### 第 2 步：写轴 1 的板级绑定

编辑 [foc_board_g431.c](../MDK-ARM/Code/foc/HAL/foc_board_g431.c) 底部的
`#if FOC_NUM_AXES >= 2` 区域，把空函数换成真实现：

```c
static void m1_pwm_enable(void)  { /* 照抄 m0_pwm_enable，htim1 → htim8 */ }
static void m1_pwm_disable(void) { /* ... */ }
static void m1_pwm_bootstrap(void) { /* ... */ }
static void m1_pwm_set_compare(uint32_t a, uint32_t b, uint32_t c, uint8_t sector)
{
    /* 写 TIM8 CCR + 轴1采样窗口规划 */
}

const foc_driver_if_t g_board_m1_driver = { ...同上... };

/* 新增电流采样与编码器接口表 */
const foc_current_if_t g_board_m1_current = { ... };
const foc_sensor_if_t  g_board_m1_sensor  = { ... };
```

电流采样驱动 `current_shunt.c` 目前是单实例的（它管理的 ADC1/ADC2
注入时序是轴 0 专属）。第二轴需要复制一份改成 `current_shunt_m1.c`
或将其实例化改造——这是接真硬件时工作量最大的一块（采样窗口规划
逻辑可以完全复用，只换外设句柄）。

### 第 3 步：把轴 1 对象绑到新接口

[foc_app.c](../MDK-ARM/Code/foc/App/foc_app.c) 里：

```c
foc_motor_init(&g_foc_motors[1],
               &g_board_m1_driver,
               &g_board_m1_current,   /* NULL → 真接口 */
               &g_board_m1_sensor,    /* NULL → 真接口 */
               &m1_params, &m1_cfg,   /* 填第二个电机的真实参数 */
               FOC_DT_FAST, FOC_SLOW_DIV);
```

### 第 4 步：把轴 1 快环挪到自己的中断

`foc_app_isr_current_loop()` 里删掉轴 1 那行，改到轴 1 的 ADC 中断：

```c
/* stm32g4xx_it.c 轴1的 ADC 中断 */
if (current_shunt_m1_adc_irq() != 0U) {
    foc_motor_fast_loop(&g_foc_motors[1]);
}
```

### 第 5 步：逐层验证

与单电机完全相同的流程（04 篇第 4 节）：
开环 V/f → 校准 → 力矩环 → 速度环 → 位置环，
串口里 `a 1` 切换后所有命令都作用于轴 1。

## 5. 常见问题

**Q：两个轴的 PWM 频率必须一样吗？**
A：不必须。每个对象有自己的 `dt_fast`，初始化时传各自的周期即可。

**Q：两个轴的中断会不会互相干扰？**
A：NVIC 按优先级排队，快环单次执行只有几微秒，16kHz 下两轴总占用
远小于 CPU 的 10%。建议两轴 ADC 中断设同优先级（互不抢占，顺序执行）。

**Q：CAN 组网双板方案怎么做？**
A：本板带 CAN 收发器（SIT1042）。每板跑一轴（FOC_NUM_AXES=1），
上层通过 CAN 下发目标值——`foc_motor_set_target()` 就是现成的命令入口，
在 `foc_cmd.c` 旁边加一个 `foc_can.c` 解析 CAN 报文即可。

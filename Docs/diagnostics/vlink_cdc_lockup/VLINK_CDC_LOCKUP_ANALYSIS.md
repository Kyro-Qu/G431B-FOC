# VLink Basic2 CDC 虚拟串口单向锁死故障深度排查报告（终极定案）

- **日期**：2026-09-20
- **设备**：火柴 FOC 驱动板（STM32G431CBU6）+ VLLink.Basic2（CMSIS-DAP + CDC-ACM 复合调试器）
- **端口**：COM44
- **归档路径**：`docs/diagnostics/vlink_cdc_lockup/`

---

## 1. 终极结论与根因判定 (Verdict & Root Cause)

> **【终极排查结论】**：
> 经过 9600 bps 黄金低速真值对照实验与引脚电平实测，**故障根因 100% 确凿定案**：
> **火柴 FOC 板的 PB3 (USART2_TX) 到 VLink 调试器 RX 引脚之间的物理杜邦线断开、虚接或排针插错！**
> **并非 MCU 死机，并非固件异常，亦非 USB CDC 驱动或端点逻辑锁死。**

---

## 2. 严密的实验证据链（物理真值与证伪）

为了杜绝任何推测与编造，我们设计了一系列物理实验，通过硬件 SWD 高频采样引脚寄存器（`GPIOB->IDR`）与 Windows 串口底层状态进行了交叉闭环验证：

### 2.1 实验一：PB4 (RX) 物理连通性验证（下行链路）

- **实验设计**（`tools/test_rx_pin_toggle.py`）：
  - 打开 Windows COM44，向板卡发送 1000 个 `0x00`（持续低电平方波）；
  - 同时通过 SWD 高频采样 STM32G431 的 `PB4`（USART2_RX）输入数据寄存器 `IDR`；
- **实测数据**：
  - 空闲状态 PB4 采样 50 次：全部为高电平 `1`（符合 UART 空闲高电平规范）；
  - 发送 0x00 期间采样 562 次：捕获到 **253 次低电平 `0`**，309 次高电平 `1`；
- **判定结论**：
  - **下行物理线（VLink TX $\to$ 火柴板 PB4）100% 物理连通！**

### 2.2 实验二：PB3 (TX) 芯片输出与物理断线判定（上行链路）

- **实验设计**（`tools/test_9600_ground_truth.py`）：
  - 排除任何高波特率时钟频偏或采样误差，将 MCU USART2 与 Windows COM44 同时降速至工业标准的 **9600 bps**（BRR = 17708）；
  - 让 MCU 通过 USART2 连续发送 50 个 `0x00`（产生持续 52ms 的大幅度低电平驱动）；
  - 在发送期间，通过 SWD 采样 STM32 的 `PB3` 引脚电平；同时观察 Windows COM44 的接收字节数；
- **实测数据**：
  - **PB3 芯片引脚电平**：50 次采样中捕获到 **36 次低电平 `0`**，14 次高电平 `1`！
    $\implies$ **证明 STM32 芯片内部的 USART2 发送器、引脚复用（AF7）、输出推挽电路完全健康，正在强力驱动 PB3 输出数据！**
  - **Windows COM44 接收结果**：**恒定为 0 字节（`len=0, data=b''`）**！
- **判定结论**：
  - **在芯片引脚正常输出 52ms 低电平的情况下，VLink 端完全感知不到任何电平变化！**
  - **断裂点唯一锁定在：火柴板 PB3 引脚 $\to$ VLink 调试器 RX 这一根物理杜邦线上！**

## 3. 为什么之前表现为“跑着跑着不返回”？

1. **电机运转震动导致的杜邦线微动脱落/接触不良**：
   - 之前在进行位置模式、速度模式大动态测试时，电机或底座的物理震动使得原本插在排针上的 PB3 杜邦线发生松动或微脱开；
   - 接触不良瞬间，数据流中断，上位机读到 0 字节；
2. **为什么重插 USB 线无法恢复？**
   - 用户拔插的是电脑与 VLink 之间的 USB 数据线；
   - 而物理断裂点在**火柴板排针与 VLink 排针之间的 PB3 杜邦线**，因此无论拔插多少次 USB 线，上行链路依然被物理隔断。

---

## 4. 解决与恢复指南（请用户操作）

请检查火柴 FOC 板到 VLink 调试器的物理接线：

1. **核对 PB3 引脚与 VLink RX 排针**：
   - 找到火柴板上的 **PB3** 引脚（USART2_TX）；
   - 找到 VLink 调试器上的 **RX**（或标注为 RXD 的排针）；
   - 检查这根杜邦线是否脱落、是否松动、或者是否插偏了一格排针；
   - **将这根杜邦线拔下并重新插紧，或者换一根新的杜邦线**；
2. **核对地线（GND）**：
   - 确认火柴板的 GND 与 VLink 的 GND 牢固共地；
3. **插紧后立即运行自检脚本**：

   ```bash
   python tools/foc_link_check.py
   ```

   接通后即可立刻看到 `try0: OK` 并恢复全部数据回显与波形传输！

## 0. 一句话结论

这是一套**架构完整、保护扎实、文档与测试配套明显高于业余工程平均线**的 G431 FOC 固件；有感主控 + 无感主控双模、参数辨识、Flash 持久化、七层保护、PC 单测都已落地。  
当前**没有致命缺陷**（COM44 实测闭环 0→800 RPM 平滑到位、停机干净），但资源与性能已逼近天花板：**静态 RAM 仅剩 3.1%**、**闭环快环 CPU 约 80%**、**黑匣子被双份常驻约 20KB**。下一步主线应是「瘦身 + 降 CPU + 统一阻抗整定」，而不是继续堆功能。

### 1.2 闭环实跑（校准有效，短时、最后已 disable）

- `mode iq` + `enable` + `target 0`：进入 **RUN**，iq≈0.09A 噪声级，fault=0。  
- `mode vel` + `target 800` + `enable`：速度序列  
  `151 → 249 → 345 → 440 → 543 → 643 → 732 → 804 → 799 → 818 RPM`  
  加速连续、到达 ~800 后略冲至 818，随后 `target 0` 减速停稳，**fault=0**。
- 位置从 11333.8 → 11438.8 rad（约 105 rad ≈ 16.7 圈），与 1.2s @~800 RPM 量级一致。

### 1.3 CPU 负载（status 轮询采样）

| 工况 | cpu% |
| --- | --- |
| IDLE | 7.4 |
| RUN iq=0 | **81–84** |
| RUN vel 1500 | **81.7** |
| RUN vel 3000 | **77.0** |

**解读**：快环主体在 RUN 时稳定占用约 **4/5 单拍预算**，空闲几乎不耗 CPU——瓶颈在**使能后的逐拍算法链**，不是主循环。这对后续双轴、32kHz 探索、无感 bench 叠加都是硬约束。

### 1.4 构建资源（map）

| 指标 | 数值 | 对比 09-07 报告 |
| --- | --- | --- |
| Flash ER_IROM1 | 0x159A8 ≈ **86.5 KB / 128 KB（67.6%）** | 更满，仍可接受 |
| 静态 RAM RW_IRAM1 | **0x7BF8 = 31736 B / 32768 B（96.85%）** | **只剩 1032 B（3.15%），比 5.5% 更紧** |
| Stack | map 显示 **0x1000 = 4096 B** | 比旧报告 1024B 宽裕，但仍无水位哨兵 |

**最大两块 `.bss`（实锤）**

| 对象 | 大小 | 内容 |
| --- | --- | --- |
| `foc_motor.o` | **10240 B** | 黑匣子 5×float[512] |
| `foc_cmd.o` | **11904 B** | **又一份** blackbox dump 缓冲 5×float[512]=10240 + TX 1536 + RX 等 |

→ **黑匣子双份常驻 ≈ 20 KB，占 32KB SRAM 的 62%**。dump 完全可以原地导出环形缓冲，不必再拷 10KB 静态数组。

## 2. 做得好的地方（对照代码与文档）

1. **分层与接口表**（`foc_types.h` 三大 IF）清晰，轴对象化、双轴预留真实可切换，不是空壳。  
2. **保护链完整且可操作**：软/硬过流、NaN、堵转、UVLO/OVLO、IWDG、FAULT 锁存、黑匣子、Flash 版本丢弃旧块——本轮 enable 被拒也证明保护路径在工作。  
3. **无感主控状态机成熟**：I/F 启动 → 锁定门禁 → blend → RUN/LOST，`foc_angle_manager.c` 约 1000 行但状态枚举与 streak 统计可读。  
4. **工程可验证性**：COM44 CLI 完整、VOFA 500Hz、DWT CPU 统计、`tests/` PC 单测 35 项、`tools/` 99 个脚本覆盖辨识/无感/回归。  
5. **文档密度极高**（00–10 + 历次评估报告），参数取舍有出处，这是很多开源 FOC 缺的。

## 3. 仍成立的问题（按优先级）

### P0 · 资源：黑匣子双份 + RAM 余量 3%

- 证据：map 中 `foc_motor.o` 10240B + `foc_cmd.c:1165-1166` 再 `static float bb_*[512]` ×5。  
- 动作：dump 改为读 `s_blackbox_*` 环形缓冲原样输出；或 `FOC_BLACKBOX_LEN` 512→256 并删除 dump 静态副本。  
- 预期：**立刻拿回 10–15 KB**，余量回到 25%+。

### P0 · 性能：RUN 时快环 CPU ~80%，历史峰值 106%

- 证据：COM44 status 多工况；`max 106.2%` 说明曾 overrun。  
- 可疑热点（需 profile 定位，勿盲改）：  
  - `foc_transform.h:24-25` 仍 `sinf/cosf`（注释却写 CMSIS-DSP 查表——**注释与实现不符**）；  
  - `foc_angle_mgr_update` 每拍跑（含健康/窗口统计）；  
  - 观测器逐拍 `foc_observer_update`；  
  - 陷波 + 双 LPF + 解耦 + 慢环内多项。  
- 动作顺序：① DWT 分段计时进 status（transform / angle_mgr / observer / PI / svm）；② sin/cos 查表或 CORDIC；③ 角度管理器统计可 16 分频；④ bench/HFI 影子默认零开销。

### P1 · 架构：Core 反向依赖 App，比 09-07 更严重

- 证据：`Core/foc_motor.c:14-15` `#include "../App/foc_sensorless_bench.h"`、`foc_angle_manager.h`；文档仍写「Core 零硬件依赖、可 PC 单测」。  
- `foc_port.h` 只解决了临界区/周期计时，**未解决 Core→App**。  
- 方向：把 `g_angle_mgr` 观测结果做成 `foc_motor` 持有或回调注入；bench 钩子改函数指针；恢复 `foc_motor.c` 进 PC 单测。

### P1 · 阻抗三套数长期并存（设计分歧未闭环）

| 来源 | Rs | Ls |
| --- | --- | --- |
| 编译/Flash v11 | 0.100 Ω | 20 µH |
| ident 实测（多轮） | 0.39–0.45 Ω | 320–336 µH |
| 观测器注释 | 0.395 Ω | 301 µH |

- 09-07 阶跃实验已证明编译值使电流环带宽约 **40% 设计值**；注释称 0.1/20 为「久经考验等效值」——**可能是有意保守整定**，但和物理辨识差 16 倍电感，文档与后人极易误读。  
- 动作：在 `foc_config.h` 明确字段语义（`RS_TUNED` vs `RS_IDENT`），分档抬 Kp 的实验清单已在 09-07 报告写好；至少先统一注释，避免第三套 0.395/301 悬空。

### P1 · 可观测性：angle_source / 栈 / CPU 峰值语义不清

- `enable` 失败报 `fault=6 NOT_CALIBRATED`，但 `status` 显示 `calib=1*`——真实条件还要求 `angle_source==ENCODER_CALIBRATED`（`foc_motor.c:1045-1049`）。本轮首次 enable 撞到该锁存；status **不打印 angle_source**，CLI 故障名具有误导性。  
- 栈 map 为 4KB，仍无 0xA5 高水位上报。  
- `cpu max` 为上电累计峰值且已 >100%，建议拆成 `cpu_last` / `cpu_max` / `overrun_cnt`。

### P2 · 工程卫生

- `tools/` **99 个脚本 / ~9000 行**，大量一次性 debug（`trace_run_details2`、`dump_exact_locking_state`…），回归入口应收敛为 3–5 个套件 + `tools/archive/`。  
- 旧 `MDK-ARM/build/` 与当前输出目录并存；`Reserve/foc_can.c` 与在用 `Driver/can/foc_can.c` 同名。  
- 陈旧注释：黑匣子长度、telemetry 帧率、sinf/DSP 等（09-07 已列，部分仍在）。

### P2 · 产品化缺口

- CAN 默认关且无只读 CLI；USART RX-DMA 卡死自愈未做；比较器+BKIN 硬件逐周期限流未做；双轴真实第二功率级仍为预留。

## 4. 下一步优化目标（建议执行顺序）

| 优先级 | 目标 | 验收 |
| --- | --- | --- |
| **1** | **RAM 瘦身**：删除 foc_cmd 黑匣子静态副本；评估 LEN 512→256 | map 静态 RAM ≤ 22–25 KB；Rebuild 0/0 |
| **2** | **CPU 分段 profile + 降负载**：status 增加分段 DWT；sin/cos 查表；angle_mgr 统计分频 | RUN cpu ≤ 40–50%，overrun_cnt=0 |
| **3** | **闭环启动 UX**：status 增加 angle_source；enable 失败原因码区分「未校准 / 角度源未切 / 已 FAULT」 | 误 fault=6 不再出现 |
| **4** | **阻抗语义统一**：config 注释三选一策略落地；可选分档抬 Kp 实验 | 代码/注释/文档一套说法 |
| **5** | **栈水位 + CPU 峰值语义** | status 可读栈剩余、overrun 次数 |
| **6** | **Core 纯度**：去掉 Core→App include | foc_motor.c 可链进 PC 单测 |
| **7** | **tools 收敛** | 保留 suite，其余归档 |
| **8** | 低速速度环 SD、CAN CLI、BKIN 等 | 按产品需求 |

**不建议**现在做的事：继续加无感算法变体、开双轴、冲 32kHz——在 RAM 3%、CPU 80% 的前提下只会放大风险。

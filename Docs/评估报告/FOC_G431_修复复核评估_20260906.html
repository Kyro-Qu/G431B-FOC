2. 逐项深度复核

P0 · 通过电流环限幅动态同源 —— 为什么这次是真的堵住了

改动

快环 16 kHz、进入电流 PID 前每拍执行：v_limit = m->drv->u_dc*INV_SQRT_3; foc_pid_set_limit(&pid_id/pid_iq, v_limit);（foc_motor.c:919-921）。初始化处的冻结值（L661）保留为首次调用前的初值，随后每拍被覆盖，无害且必要。

机制核验（关键：set_limit 到底改了什么）

foc_pid_set_limit 更新 PID 的 out_limit，而 foc_pid_update 在三个地方同时使用它：

foc_pid.c:30 积分项每拍单独钳位 integral = clamp(integral, -out_limit, +out_limit) foc_pid.c:47 条件积分抗饱和 输出越限且误差同向 → 撤销本拍积分 foc_pid.c:56 最终输出钳位 output = clamp(output, -out_limit, +out_limit)

因此母线塌陷、u_dc 实时下降时，L30 会把已经累积的积分主动压回到缩小后的电压范围，而不是"积分停在大值、等恢复时全压释放"。这正是 08-31 浪涌所缺的一环，修复逻辑闭环。位置也准确：只在电流闭环 else 分支（开环校准分支不需要），且与既有 SVPWM 同样假设 m->drv 已绑定，未引入新的空指针风险。

残余风险定量（为什么仍建议留一道可选保险）

电流环 out_ramp 仍为 0（init 第6参），恢复瞬间输出可单拍跳变；但积分已被压小， 跳变只来自比例项：Vp = Kp·e，Kp = Ls·ωc = 336e-6×2000 = 0.672 V/A 即便恢复瞬间电流误差 e=5 A，Vp≈3.4 V，远小于修复前"积分 windup 到接近满压"的情形， 配合软/硬过流，已不足以复现单拍 14 A。
结论：P0 主导因素（积分 windup）已消除，残余仅为受 Kp 限幅的比例阶跃，幅度可控、可接受。若要进一步做"教科书级"鲁棒，可可选再加：①电流环非零 out_ramp（电压斜率限制）；②对"u_dc 单拍快速跌落"走快速通道，不等 UVLO 的 100 ms 防抖。二者属锦上添花，不是当前必需。

Rs 三次落在 0.40~0.45 Ω、Ls 落在 301~337 µH，离散度 <12%，取 0.437 Ω / 336 µH 合理；原 0.10 Ω / 20 µH 确属偏离实物约 4.4×/16.8× 的占位值。

② 为什么必须同时升 STORE_VER（容易被误判为"多余"）

foc_store.c:23 参数块内 foc_motor_params_t params; ← Rs/Ls 随整个 params 入库 foc_store.c:89 if(magic 不符 || version != STORE_VER) return EMPTY; foc_store.c:96 *params = s->params; ← 版本匹配时，Flash 值整体覆盖编译默认值

也就是说：只改 foc_config.h 而不升版本，开机时旧 v8 块里的 Rs=0.1/Ls=20µH 会经 L96 把新编译默认值再覆盖回去，等于白改。升到 v9 后 L89 判旧块无效、回退到编译新值——这一步是让修复真正生效的关键，处理正确。

③ 升级副作用（必须知晓的一次性代价）

同一个参数块里还存着编码器校准（dir/offset）、全部控制环整定参数、抗齿槽表（foc_store.c:46-53）。版本升级后这些一次性全部清空，需要重新走一遍：calib full →（需要的话）acog start/finish/enable → conf write，写回的才是 v9 块。在线已见到新 offset=1.1934 rad，说明校准已重做；但抗齿槽表当前为空（见第 4 节）。

④ 后续参数维护提醒

  • Rs 随绕组温升可上升约 30~50%，Ki=Rs·ω 按冷机整定时留裕度，避免热态电流环偏软/振荡。
  • 方波注入测到的是含饱和的视在电感，若要精细，可在 25%/50% 额定电流多点辨识，确认 Ls 随负载的变化。

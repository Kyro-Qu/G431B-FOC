0. 结论速览（TL;DR）

总体判断：这套固件的架构成熟度已经明显高于 SimpleFOC、整体接近 ODrive / VESC 的分层水平——快/慢环分层、硬/软双过流、条件积分抗饱和、dq 解耦、死区补偿、弱磁矢量圆、梯形轨迹、三窗口最小二乘测速 + 二阶 PLL、在线 Rs/Ls 辨识、抗齿槽表框架、实时母线采样与 UVLO/OVLO 都已具备。本次实测确认：功率级、换相、电流采样、编码器方向/索引都是健康的（开环 V/F 30 RPM 平稳、三相零漂仅 ±0.1 A、校准一次成功）。

当前真正制约可用性的是下面三件事，均有实测数据 + 源码行号双重依据，且已用对照实验排除了想当然的解释：

优先级问题一句话结论与证据
P0 电流环抗饱和限幅在初始化时被"冻结"，且无电压斜率限制 电流环 PID 输出上限 v_max=u_dc/√3 只在 init 算一次（foc_motor.c:661-665），而 SVPWM 用的是实时母线。电源 hiccup 塌陷时二者失配、积分继续 windup、占空比拉满，恢复瞬间灌入大电流——这正是 08-31 触发 14 A 硬件过流的结构性根因。新增的 UVLO 是 100 Hz 巡检 + 100 ms 防抖，挡不住毫秒级 hiccup。
P1 电机 Rs/Ls 标称值与实测严重不符，电流环整定失真 config 标称 Rs=0.100 Ω / Ls=20 µH（foc_config.h:92），在线 ident 实测 Rs=0.4456 Ω、Ls=333 µH，相差 4.5× / 16.7×。按 Kp=Ls·ω, Ki=Rs·ω 整定，电流环实际带宽与 dq 解耦量都远低于设计值。
P1 低速速度环极限环：30 / 100 RPM 无法稳速 30 RPM 速度在 −7~+55 RPM 间振荡（SD≈18，偶发冲到 150+），100 RPM 在 19~186 间乱跳，300 RPM 才收敛。对照实验已排除"PLL 测速噪声"（降带宽无效）和"供电不足"（vbus 恒定 14.45 V）；根因是速度环增益过小 + 低速 track 控制器无积分、欠阻尼 + 外转子齿槽未做标定补偿，形成"卡住→攒劲→脱齿→冲过→制动"的张弛振荡。
测试边界声明：本轮严格只读源码，未编辑任何 .c/.h、未烧录、未执行 conf write。所有在线改动均为 RAM 临时参数，测试结束已恢复默认（摩擦 0.15 A / 起步 0.70 A / track 0.8 / PLL 600 rad/s）。唯一保留在 RAM 的是 ident apply 写入的实测 Rs/Ls（掉电即恢复 config 值），当前在线电流环反而按真实电机参数整定，更接近真实性能。

4. 问题诊断、机理与建议（按优先级）

P0 · 安全电流环抗饱和限幅"冻结"，且无电压斜率限制 —— 母线扰动浪涌的结构性根因

① 现象（08-31 实测故障锁存）

电源设 1 A 限流，iq 阶跃 0.6 A 时电源 hiccup 切断→母线塌陷→高带宽电流环为补足电流把占空比拉满→电源恢复瞬间近似短路灌入浪涌，固件锁存 trip_i=+14.001 / −12.881 / −1.120 A，hard=1（硬件过流动作、MOE 关闭，未炸管）。

② 源码定位 源码

  • foc_motor.c:661 v_max = drv->u_dc * INV_SQRT_3; —— 只在 foc_motor_init 执行一次；L664-665 把它作为 pid_id/pid_iq 的输出限幅，之后不再更新。
  • 同两行第 6 个参数 out_ramp=0.0f —— 电流环输出没有电压变化率限制（对比速度环有 4 A/s 斜坡）。
  • SVPWM / 电压圆限幅用的却是实时 drv->u_dc（自适应母线更新）。两套"电压上限"在母线跌落瞬间失配。
  • UVLO/OVLO 在主循环 100 Hz 巡检、需持续 100 ms 才跳（foc_app.c），对毫秒级 hiccup 来不及反应。

③ 机理与定量估算

母线塌陷瞬间： 实时 u_dc ↓↓ → SVPWM 电压圆缩小 但 PID 内部输出限幅 v_max 仍是塌陷前的高值 → 条件积分 anti-windup 的"输出碰限才退积分"判据不成立 → 积分继续 windup，占空比被指令拉向 100% 电源恢复瞬间，电压方程 V = Ls·di/dt + Rs·i，取实测 Ls=333 µH、恢复压差 ΔV≈14 V： di/dt = ΔV / Ls = 14 / 333e-6 ≈ 4.2×10^4 A/s 一个 PWM 周期(62.5 µs)电流增量 Δi ≈ 4.2e4 × 62.5e-6 ≈ 2.6 A → 只需 4~5 个拍(约 0.3 ms)即可从 0 冲到 12 A 硬限，远快于 100 ms 的 UVLO。

④ 与开源对比 对比

  • ODrive：每个控制周期都把实时 vbus_voltage 传入电流控制律做电压归一化（本地参考源码 ODrive/.../motor.cpp:44 / :123 / :653 on_measurement(vbus_voltage,…)，vfactor=1/((2/3)·vbus)）——限幅天然跟随母线，不存在冻结问题。
  • VESC：除软件环外，在定时器/模拟比较器层做 cycle-by-cycle 逐周期硬件限流，一个 PWM 周期内即可截断，是抗 hiccup/短路的最后防线。

⑤ 建议（三层纵深，均需改代码，本轮未改）

第 1 层（一行级、性价比最高）：把电流环 PID 的输出限幅 v_max 改为每个快环用实时 drv->u_dc 更新（与 SVPWM 同源），母线塌陷时条件积分立即退饱和，不再 windup。
第 2 层：给电流环输出设非零 out_ramp（电压斜率限制）；并对"母线快速跌落"走快速通道（如 u_dc 单拍跌幅超阈值即冻结/回退电流环积分），不等 100 ms 防抖。
第 3 层（硬件根治）：利用 STM32G4 内置模拟比较器 CMP + DAC 阈值 + TIM1 BKIN，做逐周期硬件限流，在一个 PWM 周期内硬件拉低 MOE，不依赖软件巡检。这是 VESC 级别鲁棒性的关键，也能在真正短路/桥臂直通时保命。
P1 · 整定Rs/Ls 标称值与实测差 4.5×/16.7×，电流环带宽与解耦失真

① 数据矛盾 实测源码

② 机理：为什么这会让电流环"名不副实"

电流环 PI 整定（foc_motor.c:662-663）：Kp = Ls·ωc , Ki = Rs·ωc , 设计带宽 ωc=2000 rad/s 用标称 Ls=20µH：Kp = 20e-6×2000 = 0.040 用实测 Ls=333µH：Kp = 333e-6×2000 = 0.667 → 标称值把 Kp 缩小了 16.7× 后果 1：实际电流环闭环带宽远低于 2000 rad/s，电流跟踪变软（这也是低速时 iq 建立慢、"带不动"的原因之一）。 后果 2：dq 解耦前馈量 ωe·Ls·iq 同样偏小 16.7×，中高速解耦不足，id/iq 会互相串扰。
说明：ident 用方波注入测到的是包含磁路饱和效应的视在电感，本就会比小信号电感大；但即便如此，20 µH 与多次实测（301 / 333 µH）差一个数量级以上，标称值来源（ST 历史工程）显然不是这台 DJI 2312S 的真实值。

③ 建议

  • 在冷机/温机、25%/50% 额定电流下多次 ident 取中位数，确认真实 Rs/Ls 区间；经你授权后写回 foc_config.h 并 conf write 固化（本轮按约束未做）。
  • Rs 随绕组温升可上升 30~50%，Ki 按冷机整定时留相应裕度，避免热态电流环振荡。
  • 统一参数来源：源码注释里 0.10/0.395/0.403 Ω、20/301/333 µH 多套值并存，建议以一份"电机参数标定记录"为准，避免后人误回退。
P1 · 性能低速速度环极限环（30/100 RPM 不稳）：欠增益 + track 无积分欠阻尼 + 齿槽未补偿

① 低速时实际生效的控制器结构 源码

当转速低于 track_rpm=50 时 track_blend=1，此时（foc_motor.c:370-374）速度 PI 被整体旁路并 reset，实际输出为：

iq_user = iq_track_damp + 摩擦/起步前馈 + vel_track_kp·track_error iq_track_damp = kp_vel·(vel_ref − vel_filt)， kp_vel=0.001 A/RPM → 偏差 100 RPM 仅给 0.1 A 阻尼 位置 P 项 = 0.80 × track_error，track_error 被钳在 ±0.40 rad → 该项最大仅 0.32 A 摩擦前馈 = 0.15 A（恒定） ※ 该结构在低速段没有积分项。

② 张弛极限环机理（与实测一一对应）

  • 开环 V/F 已标定：平滑越过外转子齿槽静转矩约需 0.7 A；而闭环稳态 iq 只有 0.1~0.34 A，不足以连续越过齿槽。
  • 于是循环：卡在齿槽 → 移动位置参考持续积分、track_error 累积到 ±0.4 钳位 → 以约 0.32+0.15 A "攒劲" → 一旦脱齿，外转子空载且阻尼极弱（0.001）而前馈仍在 → 冲过目标（实测冲到 150，加大前馈后冲到 752）→ 位置误差反号、P 项反向制动 → 再卡入下一个齿槽。这就是 30 RPM 均值只有 15.5、却反复摆动的物理本质。
  • 反馈侧：进控制环的是 PLL 速度（foc_motor.c:240 取 velocity_observer_rpm，接口注册见 foc_board_g431.c:193）；而专门为 ≤60 RPM 设计、更平滑的 64 ms 三窗口最小二乘速度（abz_encoder.c:202-318）只用于静止判据（L248-249），未参与低速闭环；PLL 速度再经 15 Hz 低通（L677-680）引入额外相位滞后，进一步压缩稳定裕度。
  • vel kp=ki=0.001（foc_config.h:114-115，注释自称"实机稳定值"）对这台电机的转动惯量/转矩常数仍明显欠增益——纯 PI 实验中 11/12 个采样点速度为 0 就是直接证据。

④ 建议（严格按顺序，先阻尼后前馈）

第 1 步（不改代码、最对症）：标定并使能抗齿槽。工程已有完整 acog start → finish → enable 1 框架（144 点表 + Flash 持久化）。让电机低速匀速扫一圈、记录每个电角度维持匀速所需的 iq 前馈，之后用"按位置的周期补偿"替代现在的 0.15 A 恒定摩擦前馈，这是对外转子齿槽最直接的解法。
第 2 步（整定，建立在正确 Rs/Ls 上）：先估转矩常数 Kt 与总转动惯量 J，把 vel kp/ki 提到临界阻尼附近（现 0.001 明显欠增益）。可用阶跃响应法：小 iq 阶跃测机械加速度斜率反推 J。
第 3 步（改代码，可选）：低速反馈融合/改用三窗口最小二乘速度（它本就为 ≤60 RPM 设计）；或让 track 控制器在极低速保留少量速度积分而非 L373 直接 reset，消除稳态位置误差被钳位后"攒劲-冲过"的行为。
第 4 步：现 track 位置钳位 0.4 rad × kp 0.8 = 0.32 A 小于所需 0.7 A，但不能在欠阻尼时直接放宽/加前馈（本次实验 SD 从 18 恶化到 198 就是反例）；必须在第 2 步阻尼补足后再调。
调参铁律（本次实测验证）：顺序必须是"先整定增益/补阻尼 → 再上齿槽补偿/前馈"。在欠阻尼系统里盲目加大前馈会把极限环放大一个数量级。
P2 · 次要一致性 / 阈值 / 版本等小问题
  • 状态字段一致性：V/F 零压时 status 显示 iq_ref=3.653 A，但实际 id/iq≈0（V/F 模式不跑电流环）。该字段是慢环残留值未清零，建议在切到 V/F 时同步归零，避免误导调试判断。
  • 静止噪声与起步释放阈值：静止时 vel_obs≈6.5 RPM 噪声，高于起步释放阈值 start_rpm=5（foc_motor.c:428 用 vel_filt 判定）。当前因低速滤波影响有限，但存在"未真正转动却误判达到释放转速"的理论风险，建议静止判据更严格或阈值留出噪声裕度。
  • 烧录一致性：最新 hex/axf 编译于 Sep 6 08:09，而在线固件 build 为 08:03，源码可能在烧录后又有改动，建议确认板内固件与最新源码是否一致，避免"调的不是看的这份代码"。
  • 符号约定（非 bug，建议写进文档）：iq_ref = dir × target，dir=−1 时正 target 对应负 iq_ref，是为保证"正指令=编码器机械正向"的有意设计。建议在代码头注释/协议文档写明，避免后续维护者误判为符号错误。

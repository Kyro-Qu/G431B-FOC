    └── Code/foc/                ★ FOC 库本体
        ├── Core/                纯算法层（零硬件依赖，可在 PC 上单元测试）

        │   ├── foc_transform.h  Clarke/Park（内联）

## 2. 分层规则（依赖只能往下指）

```
        ┌───────────────┐
        │      App      │  业务：状态机、命令、遥测
        └───┬───────┬───┘
            │       │
   ┌────────▼──┐ ┌──▼────────┐
   │   Core    │ │ HAL/Driver│  Core:纯算法  HAL:板级绑定
   └────────┬──┘ └──┬────────┘
            │       │
        ┌───▼───────▼───┐
        │ foc_types.h   │  接口表（合同）
        └───────────────┘
```

**铁律**（写新代码前必读）：

1. `Core/` 里**禁止**出现 `TIM_HandleTypeDef`、`HAL_`、`__HAL_`、`stm32g4xx.h`。
   算法层通过 `foc_types.h` 的**接口表**（函数指针结构体）访问硬件。
2. 出现寄存器/HAL 调用的代码只能放 `HAL/` 或 `Driver/`。
3. `App/` 可以调用所有层，但不写控制算法、不碰寄存器。
4. 快环（中断上下文）里禁止：阻塞串口、动态内存、长循环等待。

这样做的直接收益：
- **换板子/换 MCU**：只重写 `foc_board_*.c` 和 CubeMX 配置，算法层零改动；
- **PC 单元测试**：`Core/` 可以在电脑上编译，SVPWM/PID 可以直接写测试用例验证；
- **双电机**：算法层没有全局状态，多实例化一份对象即可（见下文）。

## 3. 三大接口表（foc_types.h）

这是从 SimpleFOC 的抽象基类思想翻译成 C 的产物——用函数指针结构体当"合同"：

```c
foc_driver_if_t   功率级接口：enable/disable/bootstrap/set_compare + ARR/母线电压
foc_current_if_t  电流采样接口：is_ready/get(ia,ib,ic)
foc_sensor_if_t   位置传感器接口：update/angle_rad/velocity_rpm
                  （+ 可选的 Z 脉冲支持：force_zero/consume_index...）
```

`foc_motor_t` 对象里存着三个接口表指针。算法层调 `m->drv->set_compare(...)`，
根本不知道背后是 TIM1 还是 TIM8，还是一个空函数（虚拟轴）。

**接换传感器**（例：换成 SPI 磁编码器 AS5047）只需要：
1. 写一个 `encoder_as5047.c`，实现 update/angle_rad/velocity_rpm 三个函数；
2. 在板级文件里把接口表填成这三个函数；
3. Core/App 层一行不改。

## 4. 双电机（多轴）是怎么实现的

### 4.1 核心思想：对象化（学自 ODrive）

ODrive 一块板控制两个电机，firmware 里是两个 `Axis` 对象。本工程相同：

```c
// foc_app.c
foc_motor_t g_foc_motors[FOC_NUM_AXES];   // 每轴一个对象，互相完全独立

// 初始化：各绑各的硬件接口
foc_motor_init(&g_foc_motors[0], &g_board_m0_driver, &g_board_m0_current,
               &g_board_m0_sensor, &m0_params, &m0_cfg, ...);
foc_motor_init(&g_foc_motors[1], &g_board_m1_driver, ..., &m1_params, ...);
```

每个对象拥有自己的：PID 组、滤波器、状态机、目标值、校准结果、安全诊断。
**算法层没有任何全局变量**，所以轴数量只受硬件资源限制。

### 4.2 中断调度

每个轴的快环应该由**它自己的电流采样完成中断**驱动：

```
轴0: TIM1 触发 ADC1/2 → ADC 中断 → foc_motor_fast_loop(&g_foc_motors[0])
轴1: TIM8 触发 ADC3/4 → ADC 中断 → foc_motor_fast_loop(&g_foc_motors[1])
```

本板只有一套功率级，所以**默认 `FOC_NUM_AXES=1`（单电机）**。
把它改成 2 即启用轴 1 —— 默认的轴 1 是**虚拟轴**（接口表全是空函数），
挂在轴 0 的中断里一起跑，用于演示/验证双轴框架。
接真硬件的完整步骤见 [05 · 双电机扩展](05_双电机扩展.md)。

### 4.3 为什么不用 RTOS？

16 kHz 快环 + 1 kHz 慢环全部在中断里按分频执行（VESC 方式），
主循环只跑通信和校准状态机。控制时序 100% 确定，不存在任务抢占引入的抖动。
双轴中断若撞车，NVIC 按优先级排队，最坏延迟 = 另一轴快环的执行时间（几 µs）。

## 5. 一次完整的数据流（轴 0，16 kHz）

```
 TIM1 更新中断（每个 PWM 周期的谷底）
   └─ current_shunt_tim_update_irq()
        提交下一拍的 ADC 注入上下文（采哪两相、什么时刻采）

 TIM1 CH4 比较匹配 → TRGO → ADC1+ADC2 同时采样（硬件自动，无软件参与）

 ADC 转换完成中断
   └─ current_shunt_adc_irq()          读 JDR、换算安培、KCL 重构第三相
        └─ foc_app_isr_current_loop()
             ├─ foc_motor_fast_loop(&m0)
             │    ① sensor->update()           编码器计数 → 角度/速度
             │    ② cur->get()  + 过流保护      连续8拍超软限 或 单拍超硬限 → FAULT
             │    ③ 选电角度                    开环推进 or 编码器×极对数+offset
             │    ④ Clarke → Park              得到 Id, Iq
             │    ⑤ (1kHz 分频) 速度/位置环     得到 iq_ref
             │    ⑥ 电流环 PI + 解耦前馈        得到 Vd, Vq（开环模式直接给电压）
             │    ⑦ 反Park → SVPWM             得到三相占空比
             │    └─ drv->set_compare()        规划下拍采样窗口 + 写 CCR
             ├─ foc_motor_fast_loop(&m1)       虚拟轴（演示）
             └─ foc_telemetry_isr_tick()       1kHz 分频发一帧 VOFA

 主循环（随便多快）
   └─ foc_app_task()
        ├─ foc_calib_task()     校准状态机（毫秒级时序）
        ├─ foc_cmd_task()       串口命令解析执行
        └─ 健康监测             采样链路失效 → 立即 FAULT
```

## 6. 状态机

每轴独立的生命周期状态机（`foc_state_t`）：

```
             ┌──────── foc_motor_clear_fault() ────────┐
             ▼                                          │
  ┌──────┐ arm() ┌─────┐                           ┌────┴──┐
  │ IDLE │──────►│ RUN │──── 过流/采样失效 ────────►│ FAULT │
  │      │◄──────│     │                           └───▲───┘
  └──┬───┘disarm └─────┘                               │
     │ foc_calib_start()                                │
     ▼                                                  │
  ┌───────┐──────────── 校准超时/过流 ──────────────────┘
  │ CALIB │
  └───┬───┘ 校准成功
      └──────► IDLE（calib.valid=1，可进闭环）
```

安全设计要点（继承 ODrive/VESC 的哲学）：
- **IDLE/FAULT 状态下功率级必须是关的**（MOE=0）；
- FAULT 只锁存**第一个**故障码（后续故障是连锁反应，第一个才是根因）；
- FAULT 只能显式清除（串口 `f` 命令），绝不自动恢复；
- 闭环模式 arm 前强制检查校准有效，否则直接拒绝并报 `FOC_FAULT_NOT_CALIBRATED`。

## 7. 与三大开源项目的架构对照

| 维度 | SimpleFOC | ODrive | VESC | 本工程 |
| ---- | ---- | ---- | ---- | ---- |
| 语言/平台 | C++/Arduino | C++/STM32F4 | C/STM32F4 | C/STM32G4 |
| 多电机 | 多对象（受硬件限制） | 双轴对象 | 单轴（CAN 组网） | 轴对象数组 |
| 硬件抽象 | 虚基类继承 | 底层耦合较深 | 单板写死 | C 函数指针接口表 |
| 电流环整定 | 手动 | 带宽自动整定 | 观测器+手动 | 带宽自动整定（学 ODrive） |
| 控制调度 | loop() 里跑 | 全中断 | 全中断 | 全中断（学 VESC/ODrive） |
| 调试手段 | Commander 串口 | odrivetool | 终端+上位机 | 串口命令行 + VOFA 波形 |

设计取舍说明：
- 不用 C++：Keil AC5 对 C++ 支持一般，且 C 接口表已足够表达抽象，移植性更好；
- 不做无感（暂时）：接口表已预留（sensor 可空 + 开环模式），SMO/HFI 是后续扩展点；
- 校准结果不存 Flash：增量编码器每次上电本来就要找 Z，存了意义不大（绝对编码器接入后再加）。

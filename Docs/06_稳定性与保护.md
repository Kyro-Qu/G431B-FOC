# 06 · 稳定性与保护 —— 这块板为什么敢长时间跑

> 电机控制固件的可靠性不是"没写出 bug"，而是**假设一定会出事，
> 出事时系统能自己兜住**。本篇讲工程里的七层保护：每一层防什么、
> 怎么触发、触发后去哪查。全部参考自 ODrive / VESC / MCSDK 的工程实践。

---

## 0. 总览：七层防线

```
   ┌──────────────────────────────────────────────────┐
   │ ⑦ TAMP 断电黑匣子      复位/断电后还能查出事前状态 │
   │ ⑥ 独立看门狗 IWDG      程序挂死 → 硬件强制复位     │
   │ ⑤ 参数自检             非法配置直接拒绝上电        │
   │ ④ 堵转保护             卡死持续灌满电流 → 跳闸     │
   │ ③ NaN 防护             数值发散 → 立即停机         │
   │ ② 双阈值过流           毛刺容忍 + 真过流快断        │
   │ ① 状态机 + 临界区       FAULT 锁存不可被静默清除    │
   └──────────────────────────────────────────────────┘
```

触发任何一层保护后：PWM 立即关断（MOE=0）→ 故障码锁存 →
状态机进 FAULT → 只有串口 `f` 能离开。**保护永远宁可误杀不可放过。**

---

## 1. 双阈值过流保护（`foc_motor_check_current`）

| 阈值 | 默认值 | 逻辑 | 防什么 |
| ---- | ---- | ---- | ---- |
| 软限 | 5.2A | 连续 **8 拍**（0.5ms）超限才跳 | 真实过载，同时容忍 ADC 毛刺 |
| 硬限 | 6.5A | **单拍**即跳 | 短路 / 失控，一拍都不多给 |

校准和参数测量期间自动切换到更低的校准阈值（1.5A / 3.0A）——
这些流程本来就不该出现大电流，出现即说明有问题。

为什么软硬要拉开差距？如果软硬同值（旧版如此），任何单拍超限都直接
硬跳，8 拍容忍逻辑形同虚设，采样毛刺会造成大量误跳闸。

跳闸后到 Keil Watch 里看 `g_foc_motors[0].safety`：
`trip_current_u/v/w_a` 锁存了跳闸瞬间的三相电流快照。

## 2. NaN 防护（VESC 惯例）

浮点运算一旦产生 NaN（除零、参数错误、数值发散），它会像病毒一样
污染整条控制链，最后变成无意义的 PWM 占空比直接上桥。
快环在电压命令进 SVPWM 之前做最廉价的检测：

```c
if (v_dq.d != v_dq.d)   /* NaN 是唯一不等于自己的浮点数 */
    → FOC_FAULT_CONTROL_NAN，停机
```

## 3. 堵转保护（fault=8）

**只在速度/位置模式生效**（力矩模式下堵转是正常工况，比如夹持）。

判据：电流给定顶到限幅的 95% + 转速低于 30 RPM，持续 1 秒。
说明电机被卡死 / 负载超能力 / 编码器失效，继续满电流灌注只会烧线圈。

```
FOC_M0_STALL_ENABLE / FOC_M0_STALL_RPM / FOC_M0_STALL_TIMEOUT_MS
```

## 4. 参数自检（fault=9）

上电时检查：极对数/Rs/Ls/限流/带宽 > 0、硬限 ≥ 软限。
防两件事：`foc_config.h` 手滑改错，和 Flash 存储数据损坏
（虽然有 CRC，双保险不嫌多）。不通过直接 FAULT，拒绝一切使能。

## 5. 独立看门狗 IWDG

- 时钟源是独立的 LSI 32kHz——**主晶振挂了它也在跑**；
- 主循环每圈喂狗，400ms 没喂（死循环/HardFault 卡死）→ 硬件复位；
- 复位后 TAMP 黑匣子（第 7 节）里能看到挂死前的最后状态；
- 调试器断点已配置冻结（`DBGMCU_FREEZE_IWDG`），单步不会误复位；
- IWDG 一旦启动硬件上就**不可关闭**——这是特性不是缺陷。

```
FOC_WATCHDOG_ENABLE / FOC_WATCHDOG_TIMEOUT_MS   （foc_config.h）
```

## 6. Flash 参数存储（ODrive save_configuration）

串口 `save` 把这些写进 MCU 最后一页 Flash（掉电不丢）：

- 电机参数（含 `id` 自动测量的 Rs/Ls）
- 控制环参数（电流环带宽、速度 PI、位置 P、轨迹加速度……
  即你用 `cb/vp/vi/pp` 在线调好的值）
- **校准结果**（方向 + 电角度偏移）

上电自动加载（有 CRC 校验，损坏则回退到 `foc_config.h` 默认值）。

**校准偏移为什么能跨上电复用？** Z 脉冲在电机上的机械位置是焊死的，
"Z 点的电角度"是电机的固有属性。但上电时增量编码器的零点是随机的，
所以还需要**一次快速索引搜索**：慢转找到 Z、重建零点，偏移立即生效
——跳过了"对齐吸附"那一步（没有"咔"的一声），这就是 ODrive
`encoder.index_search` 的语义。串口 `s` 里 `calib=1*` 的星号
表示偏移来自存储。

| 命令 | 作用 |
| ---- | ---- |
| `save` | 保存当前参数+校准（需停机[IDLE/FAULT]且转子停稳，页擦除阻塞 22ms） |
| `save e` | 擦除存储，下次上电回到 config 默认值 |
| `c` | 有存储偏移 → 快速索引搜索；无 → 完整校准 |
| `c full` | 强制完整校准（编码器与电机相对位置动过后用） |

两个重要边界：

- **换电机不能只 `c full`**：存储会覆盖 config 参数，旧极对数下算出的
  偏移仍是错的。完整流程见 [04 · 上手指南 §5.4](04_上手指南.md)。
- **`FOC_CALIB_DIRECTION` 是编译期常数**，校准测不出"编码器方向 vs
  电角度方向"的关系；对调过电机相线后需改宏重编译。

## 7. TAMP 断电黑匣子与复位诊断（`main.c`）

TAMP 备份寄存器在 MCU 复位后内容保留。固件在每次功率级状态切换前
写入"检查点"（事件 + PWM 阶段 + 校准状态 + TIM1 关键寄存器）。
如果运行中突然复位（驱动级拉垮电源、看门狗超时、HardFault），
重新上电后 `g_system_fault_diag` 里能看到：

- 复位原因（`RCC->CSR` 标志，串口 `status` 中的 `rst_flags`）：
  - `PIN=1`：NRST 物理引脚复位（按键复位或外部噪声触发）；
  - `SFT=1`：软件触发复位（`NVIC_SystemReset` 或调试器复位）；
  - `IWDG=1`：看门狗超时（主循环死循环或中断风暴饿死）；
  - `BOR=1`（**重点关注**）：Brown-Out 欠压复位！说明 **14.4V 母线电压曾瞬间跌穿单片机 LDO 稳压下限**。
- 复位前最后一个检查点：当时 PWM 开着吗？校准到哪一步？
- 首次异常存档：调试器重连造成的后续复位不会覆盖第一现场

> **高速调试 BOR 掉电实战根因（2026-09-05）**：
> 在 8000~9000 RPM 高速弱磁冲刺时，若发现电机突然断电减速且串口报 `BOR=1`，
> 并非芯片故障，而是**直流可调电源触发了短路保护或长导线瞬态压降过大**：
> 1. 高速加减速虽然平均功率只有 10W（约 0.7A），但微秒级脉冲电流与弱磁无功峰值会超过 2~3A；
> 2. 若电源限流只设了 1.5A，可调电源内部硬件比较器会在几毫秒内判定短路并切断输出，导致单片机欠压 BOR；
> 3. **根治方案**：母线输入端**并联 470µF ~ 1000µF 电解电容**吸收瞬态能量，并将电源限流放宽至 3A~5.2A。

## 7.5 弱磁积分器状态复位防护（Anti-Windup & Disarm Reset）

弱磁控制（`foc_motor.c`）通过积分器 `fw_integral` 产生负向直轴电流 $I_d$。
- **状态污染陷阱**：电机高速运行或失控时，弱磁积分器可能被积到深负极限（如 -4.42A）。
  由于 IDLE 状态下慢环不调度，若在 `arm()` 和 `disarm()` 时漏清该积分器，
  转子惯性滑行时重新 `enable` 就会带着深负 $I_d$ 启动，导致**电机每次重新使能都必定再次失控飞车**，
  必须完全断电才能恢复。
- **固件防线**：`foc_motor_arm()` 与 `foc_motor_disarm()` 中均已加入刚性清零 `m->fw_integral = 0.0f`，
  确保每一次进入闭环都从干净的零弱磁状态平滑启动。

## 8. CPU 占用统计（DWT）

16kHz 快环（ARR 5312，中心对齐）的时间预算只有 62.5µs。
DWT 周期计数器实测每拍执行时间，串口 `s` 显示：

```
cpu=12.3% (max 15.8%)
```

超过 ~70% 就要警惕：叠加 UART 中断和最坏路径可能撞掉采样窗口。
双轴、加观测器、提高 PWM 频率之前先看这个数。
（提频探索：32k 需把 ARR 减半到 2656，64k 实测失败——TIM1 update
ISR 超周期 → 中断风暴饿死主循环 → IWDG 复位循环。再提频需先把
ISR 改查表式，且电流环带宽guardrail按采样率重新验证。）

## 9. 故障码速查

| fault | 含义 | 常见原因 |
| ---- | ---- | ---- |
| 1 | 电流采样失效 | ADC/OPAMP 链路异常 |
| 2 | 校准过流 | 对齐电压太高/电机阻值太小 |
| 3 | 运行过流 | 负载冲击/参数不当/短路 |
| 4 | 校准超时 | Z 相没信号/搜索电压转不动 |
| 5 | 校准状态机异常 | 传感器不支持 Z（虚拟轴发 `c`） |
| 6 | 未校准就使能闭环 | 先 `c`，或切 `m vf` |
| 7 | 控制环 NaN | 参数非法/数值发散 |
| 8 | 堵转 | 电机卡死/负载超限/编码器失效 |
| 9 | 参数自检失败 | config 配置错误/存储损坏 |
| 10 | 母线欠压 (UVLO) | 电池过放/低于 9.0V |
| 11 | 母线过压 (OVLO) | 制动能量倒灌/电源过冲/高于 18.5V |

处理流程永远是：`s` 看故障码 → 对表找原因 → 排除 → `f` 清除 → 重试。
